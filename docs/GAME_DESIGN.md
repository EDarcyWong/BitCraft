# 比特工坊：玩法设计草案

状态：设计草案，所有功能均待实现。本文用来约束第一版范围，并说明后续玩法如何衔接。

[项目介绍](../README.md) · [开发路线](ROADMAP.md)

## 1. 玩家体验

玩家是一名数字工坊的“小小工程师”，从连接开关和灯开始，完成越来越有趣的制作委托。每次挑战只引入少量新概念，玩家通过搭建和观察理解原理。

体验目标：

- 接线后立即看见结果，失败时能知道哪里需要调整。
- 入门关卡以三到十分钟为设计目标，没有强制倒计时。
- 先让作品正确工作，再提供减少元件等可选优化目标。
- 不以惩罚、体力或资源消耗阻止玩家反复尝试。
- 关卡教会一种能力后，让玩家在自由沙盒里继续使用。

## 2. 三层递进

### 数字电路沙盒

拖入元件，将输出引脚连接到输入引脚，切换开关并观察导线与输出灯。元件说明用一句话描述行为，并提供简短真值表。

组合出更复杂的电路后，后续版本允许将电路封装为带命名输入、输出的模块，存入个人元件库。

芯片封装是后续成长的关键：从半加器、全加器到多位加法器，玩家复用自己做出的部件，同时能够展开检查内部电路。

### 计算机组装

这里的“组装”指用逻辑模块构造一台能运行的简化计算机。推进顺序为：

```text
逻辑门 → 加法器与选择器 → 时钟与寄存器 → ALU 与内存 → 简化 CPU
```

第一台计算机暂按 8 位教学机器设计，具体字长与指令集在进入此阶段时确定。玩家应能观察数据如何在部件间流动，而不只是看到最终计算结果。

### 编程闯关

先提供能运行示例程序的参考计算机，再允许玩家使用自己搭建且通过基础校验的计算机。编程入口拟采用少量可读的类汇编指令，围绕数据读写、运算、跳转与输出展开。

后续关卡可包括加总一组数字、寻找最大值、输出灯光序列。程序支持暂停、单步和查看寄存器；无限循环由步数上限和停止按钮处理。

在显示和键盘模块完成后，远期挑战是输出 `HELLO`，再运行简单的弹球或贪吃蛇游戏。显示与输入设备属于后续扩展，不加入首版。

## 3. 第一版交互

画面由元件栏、中央网格画布、选中元件说明和关卡任务区组成。

| 玩家动作 | 预期反馈 |
| --- | --- |
| 放置或移动元件 | 吸附到网格，显示输入与输出方向 |
| 连接引脚 | 只接受合法的“输出 → 输入”连接 |
| 切换输入开关 | 更新数值、导线状态和输出灯 |
| 选中元件或导线 | 显示名称、当前状态和删除入口 |
| 缩放或平移 | 保留元件位置，方便观察较大的电路 |
| 提交关卡 | 显示通过结果，或一组失败输入及期望输出 |

信号同时使用颜色与 `0/1` 标记，避免只靠颜色区分。编辑错误应在对应引脚、导线或元件附近指出，并保留玩家的其他搭建内容。

导线的低电平使用暗色，高电平使用发光与流动光点，帮助玩家追踪信号路径。动画只解释已计算出的状态，不作为真实传播延迟；提供减弱或关闭动画的选项。

基础快捷键拟包括删除、取消接线和撤销；具体键位在实现时统一定义。触屏交互放到后续阶段。

## 4. 首版元件

| 元件 | 输入 | 输出 | 行为 |
| --- | --- | --- | --- |
| 输入开关 | 无 | 1 个 | 玩家设置为 `0` 或 `1` |
| 输出灯 | 1 个 | 无 | 输入为 `1` 时点亮 |
| NOT | 1 个 | 1 个 | 反转输入 |
| AND | 2 个 | 1 个 | 两个输入都为 `1` 才输出 `1` |
| OR | 2 个 | 1 个 | 至少一个输入为 `1` 就输出 `1` |
| XOR | 2 个 | 1 个 | 两个输入不同时输出 `1` |

导线负责传递信号，不作为逻辑运算元件。首版信号宽度固定为 1 位；多位总线、时钟、寄存器和内存不进入首版。

## 5. 数字逻辑模拟规则

- 有效逻辑值只有 `0` 与 `1`；未连接或上游无效时显示“未定义”，不默认为 `0`。
- 每个输入引脚最多有一个驱动源；一个输出可以连接多个输入。
- 不允许输入接输入、输出接输出，也不通过“最后写入获胜”处理驱动冲突。
- 导线在画面上交叉不自动相连，只有明确的引脚连接才构成电路。
- 首版只接受无环的组合电路；检测到组合环路时拒绝该次连接并指出原因。
- 输入变化后按依赖顺序求值，再统一刷新显示；装饰动画不影响逻辑结果。
- 相同电路与输入必须得到相同输出，不模拟真实传播延迟、噪声、电压或电流。
- 进入时序电路阶段后再引入离散时钟步：先求组合逻辑，再让所有寄存器基于同一份旧状态同步更新，最后重新求值并刷新输出。组合环路依然需要诊断。

“未定义”是编辑与诊断状态，不是一种可用于解题的第三逻辑值。关卡必需输出存在未定义状态时不能通过。

## 6. 六个入门关卡

| 关卡 | 委托 | 可用元件 | 验证目标 |
| --- | --- | --- | --- |
| 01 点亮工坊 | 用开关控制门口的灯 | 开关、灯、导线 | `Y = A` |
| 02 反向指示灯 | 开关关掉时指示灯亮 | 增加 NOT | `Y = NOT A` |
| 03 双重许可 | 两个开关都打开才放行 | 增加 AND | `Y = A AND B` |
| 04 任意呼叫 | 任意一个开关都能呼叫 | 增加 OR | `Y = A OR B` |
| 05 状态不同 | 两个开关状态不同才提示 | 使用已解锁元件，过关解锁 XOR | `Y = A XOR B` |
| 06 第一台加法器 | 显示两个 1 位数相加的和与进位 | 增加 XOR，使用两个输出灯 | `S = A XOR B`，`C = A AND B` |

第 05 关允许使用 NOT、AND、OR 组合实现 XOR，提示逐步引导到“一个开、另一个关”的两种情况。第 06 关为半加器，不引入进位输入。

后续委托可将时钟与状态机包装为交通灯，把比较与记忆包装为密码锁，把顺序控制包装为电梯。每项委托应有对应的可观察输入、输出和明确通关条件。

## 7. 关卡判定与提示

每关定义固定且有名称的输入、输出端口、可用元件、目标真值表和教学提示。玩家可以自由组织内部电路，端口身份不随元件移动而变化。

首版关卡最多两个输入，因此验证器枚举所有输入组合；不只检查玩家当前开关状态，也不要求电路长得和标准答案一样。

失败反馈分为两类：

- 电路无效：指出未连接的必要输入、无效接线或无法求值的输出。
- 逻辑不符：展示一个反例，例如“当 A=1、B=0 时，期望 Y=0，实际 Y=1”。

提示按“目标解释 → 输入组合提示 → 搭建思路”逐步展开。正确完成即可过关，元件数量和完成时间不作为首版强制条件。

## 8. 沙盒、奖励与保存

自由沙盒直接提供首版基础元件，方便玩家实验；关卡中的解锁只用于安排学习顺序。奖励以新关卡、新元件说明和作品展示为主。

首版只规划本地保存，记录电路布局、连线、关卡进度和存档格式版本；作品可导出为 JSON 文件并重新导入。导入时验证结构、元件类型与连接关系，失败时保留当前作品并给出原因。

账号、云同步、作品社区与多人协作不在首版范围内。

## 9. 实现边界

实现时将电路求值、画布交互、关卡验证和存档拆开。模拟结果不依赖画面帧率，关卡验证器复用同一套求值规则，导入数据不能执行脚本。

原始讨论提出的候选方案是 Vue 3 + TypeScript 负责界面、PixiJS 负责画布，Phaser 作为备选。这里仅记录选型方向，不视为已经确认或安装的技术栈；原型阶段验证交互与求值需求后再确定版本和构建工具。

架构职责拟分为电路编辑器、独立模拟引擎、计算机模块、关卡系统、存档系统与界面。首版只实现其中需要的职责，不预先搭建 CPU、账号或后端服务。

## 10. 待原型验证

- 鼠标接线是否容易理解，错误提示是否能帮助玩家自行修正。
- 信号流动的表现形式与动画速度。
- 第 05 关的难度是否需要拆分为额外教学步骤。
- 一个画布支持多少元件，才能兼顾流畅性与搭建自由。
- 8 位计算机和类汇编入口的学习门槛是否合适。

先验证基础搭建是否有趣，再决定后续规模和美术投入。

## 11. 设计来源与取舍
